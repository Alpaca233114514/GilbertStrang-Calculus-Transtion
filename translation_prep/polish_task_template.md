# 单节润色任务模板

本文件供并行润色任务使用。每次只处理一个 `translation_draft/*.zh-CN.md` 文件。

## 先读

1. `translation_prep/polish_guide.md`：本轮规范。
2. `translation_draft/08_ch01_sec03.zh-CN.md`：已认可的样稿。
3. `git diff HEAD -- translation_draft/08_ch01_sec03.zh-CN.md`：改动幅度与手法。
4. 指定译稿全文。
5. 需要核对意思时，读 `translation_prep/source_text/` 中该节对应的英文页。

## 目标

提升中文的灵动性与适度通俗性，让文字像 Strang 在课堂上讲课；知识内容一个字都不能改。

## 硬约束

- 公式（`$...$`、`$$...$$`）逐字保留，包括 `\text{}` 内中文；不改公式编号。
- 所有数字、单位、上下限、定义域、条件、量词、否定词保留。
- 术语区分保留（速度/速率、距离/路程/位移、函数/函数值等）。
- 标题、页码注释、图号、表号、图片路径、表格行、习题编号、列表层级、译注/原注/† 脚注一律不动。
- 不增删例子、解释、事实、比喻；不加原文没有的玩笑或网络语；保留第一人称。
- 只改正文叙述、例题叙述、图注的行文；公式行、表格行、标题不碰。
- **不要移动行间公式的位置。** `$$...$$` 公式块必须保持原有顺序和位置。行内公式可以随句子重组换位，但不能增删或改写。

## 做法

- 逐段读，先确认意思，再改。拆长句、去翻译腔、把名词化改成动作、关键处用短句；一段有一两处亮点即可，整体仍是教材。
- 不要为了“通俗”把“若…则…”改成“只要…就…”，不要把“近似/可能/通常”说死。
- 不要改动“来源/状态”那一行。
- 保存后运行：
  ```
  python translation_prep/tools/check_polish.py translation_draft/XX.md
  ```
  必须显示“✓ 公式、数字、图片、标题、表格、注释均未变”。行内公式换位会给出提示，确认语义未变即可；行间公式顺序变了则必须改回。
- 再运行 `git diff --stat` 与 `git diff`，逐段回读，确认没有语义漂移；汉字数宜保持在原文的 90%–108%。

## 汇报

- 文件与 checker 最后一行。
- 汉字数变化、改动行数。
- 主动放弃或拿不准的 2–4 处（说明原因）。
- 明确声明：没有改动公式、数字、条件、术语、结构、译注。
- 只编辑指定文件，不改 README、进度表或其他译稿。
- **只改灵动性不足的句子**：先通读一遍，标出读起来僵、拗口、翻译腔重的地方，只改这些；通顺的句子保持原样。改动行数一般不超过全文 25%，汉字数与基线的差宜在 ±3% 以内。不要为了显得改过而硬改。
