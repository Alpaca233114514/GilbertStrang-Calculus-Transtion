# 润色规范：灵动性与适度通俗性（2026-10-25）

本轮任务不是重译，而是在现有初译稿上做**行文润色**。目标有两条：让中文读起来更像 Gilbert Strang 本人在讲课——有节奏、有画面、有提问和停顿；让抽象表述适度落地，不端着。**知识内容本身一个字都不能改。**

## 一、硬约束（违反即返工）

1. **公式不动。** 行内、行间公式逐字保留，包括 `\text{}` 里的中文、上下标、编号、标点。公式若有错，记入 `issues.json`，本轮不改。
2. **数字、单位、上下限、定义域、条件、量词不动。** “约”“可能”“通常”“至少”“恰好”这类限定词不得为了顺口删掉或加强。
3. **术语区分不动。** 速度／速率、距离／路程／位移、位置／累计路程、函数／函数值、增量／微分、充分／必要，按原稿区分，不因通俗而混用。
4. **结构不动。** 标题、章节号、页码注释、图号、表号、习题编号、列表层级、引用块、表格行、图片路径均保持原样；图注可润色，但不得增删图内信息。
5. **信息不增删。** 不删例子、不合并段落丢信息、不补原文没有的解释或证明、不把作者的自嘲和题外话“优化”掉。
6. **译注不动。** 译注、原注、† 脚注保持原内容与原位置；语言不顺也先留着，另记。
7. **保留第一人称与作者口吻。** “我”“你”“我们”按原文，不改成 impersonal 的“本文”“人们”。

## 二、语言手法

### 1. 拆长定语，让主语早点出现

- 原：从几何上说，平均值是一条直线的斜率，而非曲线在一点处的斜率。
- 改：几何上，平均值是一条直线的斜率，不是曲线在某一点的斜率。

### 2. 名词化改成动作

- 原：求 $v(10)$ 的办法，是不断缩短时间间隔。
- 改：要得到 $v(10)$，就得把时间间隔一再缩短。

- 原：对……进行讨论 → 改：讨论……
- 原：作出判断 → 改：判断……

### 3. 一句一个意思，关键处用短句

- 原：它更接近 $t=10$ 时的速度，但仍不精确。
- 改：这更接近 $t=10$ 时的速度，可还是不够精确。

- 原：**结论：$t=10$ 时的速度为 $v=20$，这就是曲线在该处的斜率。**
- 改：**结论：$t=10$ 时速度为 $v=20$；这也正是曲线在该点的斜率。**

### 4. 把“读者会怎么想”写出来（只限原文已有此意）

- 原：速度常被说成距离除以时间，但速度变化时怎么办？
- 改：人们常说，速度就是距离除以时间。可速度在变的时候，这招还管用吗？

### 5. 用具体动作代替抽象判断（不新增事实）

- 原：驾驶者踩下油门，汽车加速，速率表读数均匀上升。
- 改：司机一踩油门，车就加速，速率表的指针稳稳往上爬。

### 6. 删掉多余的“的”“所”“被”“进行”

- 原：这是我们第一次遇到常让人头疼的“中值定理”。
- 改：这是我们头一回碰到那个常让人头疼的“中值定理”。

### 7. 让转折、因果显形

- 原：微积分也许是一门好课，却不是魔术。
- 改：微积分也许是门好课，可它不是魔术。

### 8. 保留幽默，但别抢戏

- 原：我不确定警察能否因此开罚单。
- 改：警察凭这个能不能开罚单，我不好说。

一段里有一两处这样的亮点就够了；通篇抖机灵会盖过数学。

## 三、通俗的边界

可以：

- 用“这招”“一踩油门”“往上爬”“绕不过去”这类课堂口语；
- 把“在此情形下”改成“这时”，把“因而”改成“于是”“所以”；
- 用问句、破折号、冒号制造讲解节奏。

不可以：

- 加原文没有的比喻、段子、网络流行语、方言；
- 用“咱们”“小伙伴”“搞事情”这类与教材不符的口吻；
- 为了顺口把条件句改成断言，把“近似”说成“等于”；
- 把严谨的“若……则……”改成含糊的“只要……就……”（除非逻辑确实等价）。

## 四、分层处理

| 层级 | 处理力度 |
| --- | --- |
| 章引言、节正文 | 重点润色，句法与节奏都可调 |
| 例题叙述 | 润色叙述，题目条件与数字不动 |
| 图注 | 轻度润色，图内信息不动 |
| 习题题干 | 只改生硬处，保持题干简短、条件清楚 |
| 习题解答/提示 | 轻度润色，不补步骤 |
| 译注、原注 | 不动 |
| 索引、公式表、目录 | 不润色 |

## 五、流程

1. 读中文稿，并对照 `translation_prep/source_text/pXXXX.txt` 中对应英文页；确认每段在说什么。
2. 只改正文行（公式行、表格行、标题、页码注释不碰）。
3. 跑检查：
   ```
   python translation_prep/tools/check_polish.py translation_draft/XX.md
   ```
4. `git diff` 逐段回读，重点核对：数字、条件、术语、否定、译注。
5. 在 `translation_prep/polish_progress.md` 标记 `polished`；结构检查通过标 `checked`。
6. 润色不等于复审，不把 `reviewed` 改为 true，不改初译状态说明。

## 六、自检清单

- [ ] 定义域、条件、量词、否定没有松动
- [ ] 速度/速率、距离/路程等术语没有混
- [ ] 标题、图号、页码、习题编号没动

- [ ] 读起来像讲课，而不是像论文摘要

## 七、本轮补充口径（2026-10-26，用户指示）

- **只挑灵动性不足的句子改**：拗口的长定语、翻译腔、名词堆叠、一句话塞三个转折。读起来已经顺的句子，一个字都不要动。
- 不再追求整节重写。改动行数一般控制在全文 25% 以内，汉字数与基线相差宜在 ±3% 以内。
- 凡改过的句子都要能说出「原来僵在哪」；说不出来的改动就是多余的，删回去。
- 原因是前几轮出现过把通顺句改坏、顺手改掉量词与条件的越界；改动面越大，越界机会越多。逐句重写只留给初译本身就不通的地方。
